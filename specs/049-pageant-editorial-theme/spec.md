## 1. Clarifications & Resolved Decisions

### Session 2026-10-23
- **Q1: Where does the Haute-Couture Pageant Editorial design originate?**  
  → **A**: From the editorial prototype in [`public/prototypes/pageant-voting.html`](file:///public/prototypes/pageant-voting.html) (Ms. Tala 2026), featuring obsidian surfaces (`#0B0C10`, `#12141C`), champagne gold accents (`#CBB279`), and Cormorant Garamond typography.
- **Q2: How are theme-specific styles isolated so default events remain untouched?**  
  → **A**: All Pageant Editorial styles are strictly scoped via CSS variables and the container attribute `[data-event-theme="pageant-editorial"]` generated by [`EventThemeProvider`](file:///src/features/events/theme/EventThemeProvider.tsx). Default events (`ELECTA_DEFAULT`) use `[data-event-theme="electa-default"]` and retain Electa's clean Opal slate design system with zero visual changes.
- **Q3: Which public event page components require theme-adaptive styling?**  
  → **A**:
    1. [`EventBanner`](file:///src/features/events/components/EventBanner.tsx): Editorial hero masthead, champagne typography, and refined status badges.
    2. [`EventCountdown`](file:///src/features/events/components/EventCountdown.tsx): Architectural countdown timer with champagne numerals, vertical dividers, and compact mobile stacking.
    3. [`ContestantCard`](file:///src/features/contestants/components/ContestantCard.tsx): 4:5 portrait card with obsidian surface, champagne sash tags, Cormorant Garamond typography, and refined action buttons.
    4. [`BoostVoteModal`](file:///src/features/payments/components/BoostVoteModal.tsx): Scoped luxury dark aesthetic with champagne borders and accents.
- **Q4: How are font families loaded and rendered without layout shifts?**  
  → **A**: Cormorant Garamond and Plus Jakarta Sans are mapped in `THEME_REGISTRY.PAGEANT_EDITORIAL` via CSS variables `--font-heading`, `--font-body`, and `--font-serif` with robust system serif and sans-serif fallbacks. Next.js font or Google Web Fonts link ensures fast asynchronous loading.
- **Q5: What are the WCAG 2.1 AA accessibility contrast constraints?**  
  → **A**: All text against dark backgrounds (`#0B0C10`, `#12141C`) must achieve at least 4.5:1 contrast (e.g. `#F9F9FB` provides ~18:1; `#CBB279` on `#0B0C10` provides 8.4:1; `#9BA3B4` provides 6.7:1). Interactive controls must have at least 3:1 contrast against adjacent backgrounds.
- **Q6: Does switching to the Pageant Editorial theme alter voting, tallying, or payments?**  
  → **A**: Absolutely not. Functional logic (free voting via `FreeVoteButton`, boost payment intents, QR Ph generation, category filtering, search) remains 100% functionally identical.

## 2. Overview & Business Value

Electa empowers organizers to run diverse competition genres—from hackathons to beauty pageants. While the default Opal Slate theme is clean and functional for academic and civic elections, prestigious pageants and formal galas demand an immersive, high-fashion visual identity.

The **Haute-Couture Pageant Editorial Theme** (`PAGEANT_EDITORIAL`) brings the production aesthetic of national beauty pageants to Electa:
1. **Atmosphere**: Deep Obsidian surfaces (`#0B0C10`, `#12141C`), subtle ambient borders (`rgba(255, 255, 255, 0.08)`), and Champagne Gold accents (`#CBB279`).
2. **Typography**: Editorial serif headings (`Cormorant Garamond`) paired with precise modern body text (`Plus Jakarta Sans`).
3. **Architectural Countdown**: Distinctive architectural digit blocks with vertical dividers and compact mobile responsiveness.
4. **Editorial Contestant Dossier**: High-fashion 4:5 portrait cards with sash badge placement, Cormorant Garamond candidate typography, and dual-action buttons (Free Vote + Boost).
5. **Theme Parity & Zero Regressions**: Zero impact on events configured with `ELECTA_DEFAULT`.

## 3. User Scenarios & Testing

### User Story 1 - Pageant Editorial Visual Theme Rendering (Priority: P1) 🎯 MVP

An event organizer configures a pageant event with `theme = "PAGEANT_EDITORIAL"`. When a voter navigates to `/events/[slug]`, the page renders with the deep obsidian atmosphere, champagne gold accents, Cormorant Garamond serif headings, and architectural countdown timer.

**Why this priority**: Core visual delivery of the theme skin as specified in Jira VS-121.

**Independent Test**: Mount the public event page with an event having `theme = "PAGEANT_EDITORIAL"`. Verify `[data-event-theme="pageant-editorial"]` is present and component styling matches the prototype tokens.

**Acceptance Scenarios**:
1. **Given** an event configured with `theme = "PAGEANT_EDITORIAL"`,
   **When** a voter navigates to `/events/[slug]`,
   **Then** the page displays the deep obsidian background (`#0B0C10`), champagne gold accents (`#CBB279`), Cormorant Garamond serif headings, and architectural countdown timer.
2. **Given** an event configured with `theme = "ELECTA_DEFAULT"`,
   **When** a voter navigates to `/events/[slug]`,
   **Then** the page renders with Electa's clean Opal Slate-50 background and Sky Blue accents without any visual regression.

### User Story 4 - Responsive Mobile & Desktop Viewport Adaptation (Priority: P2)

A voter views the pageant event on a mobile phone (375px width) or a desktop display (1200px width). The layout adapts fluidly: the architectural timer compacts into a neat stacked card, and the contestant roster grid transitions from 1 column on mobile to 2 columns on tablet and 3 columns on desktop without horizontal scrolling or clipped content.

**Why this priority**: Over 70% of pageant voting occurs on mobile devices via social media links.

**Independent Test**: Verify CSS grid classes (`grid-cols-1 sm:grid-cols-2 lg:grid-cols-3`) and container widths at 375px and 1200px.

**Acceptance Scenarios**:
1. **Given** a 375px mobile viewport,
   **When** viewing the pageant event page,
   **Then** no horizontal overflow occurs, the architectural timer digits scale down cleanly, and contestant cards render at full width with proper 4:5 proportions.
2. **Given** a 1200px desktop viewport,
   **When** viewing the pageant event page,
   **Then** the contestant roster renders in a 3-column grid with 28-32px spacing.

### User Story 5 - WCAG 2.1 AA Color Contrast Parity (Priority: P2)

All text, labels, status badges, and interactive controls rendered under the Pageant Editorial theme must strictly comply with WCAG 2.1 AA contrast requirements across both body text (>= 4.5:1) and large text / interactive UI components (>= 3:1).

**Why this priority**: Compliance with repository accessibility rules (`accessibility-colors.md`) and Electa Constitution §VI.

**Independent Test**: Execute `node .agents/skills/accessibility-colors/scripts/check-contrast.mjs` on theme color pairings.

**Acceptance Scenarios**:
1. **Given** body text (`#F9F9FB`, `#9BA3B4`) on obsidian backgrounds (`#0B0C10`, `#12141C`),
   **When** contrast is calculated,
   **Then** `#F9F9FB` achieves >= 17:1 contrast and `#9BA3B4` achieves >= 6.5:1 contrast (both >= 4.5:1).
2. **Given** champagne accents (`#CBB279`) on obsidian backgrounds,
   **When** used for large headings or button borders,
   **Then** contrast is >= 8:1 (exceeds 3:1 requirement).
3. **Given** contestant portrait photos,
   **When** text overlays are positioned on the image,
   **Then** a dark gradient scrim overlay (`bg-linear-to-t from-slate-950 via-slate-950/60 to-transparent`) ensures text remains legible regardless of photo luminance.

### User Story 6 - Uncompromised Core Functional Integrity (Priority: P1)

When an event adopts `PAGEANT_EDITORIAL`, all underlying voting mechanisms (daily free vote, voter authentication modal, Turnstile check, boost vote packages, QR Ph payment modal, contestant profile modal, division/category filters, and live search) execute identically without regressions or altered API contracts.

**Why this priority**: The theme skin must be purely presentation-driven without disturbing mission-critical voting workflows.

**Independent Test**: Execute existing voting and payment unit tests to guarantee zero regressions.

**Acceptance Scenarios**:
1. **Given** a user casting a free vote on a `pageant-editorial` event,
   **When** the free vote button is clicked,
   **Then** voter authentication, daily vote limit checking, and vote recording function identically to default events.
2. **Given** a user clicking "Boost Vote",
   **When** `BoostVoteModal` opens,
   **Then** pricing tiers, PHP pricing calculation, and QR Ph generation proceed without failure.

## 4. Requirements & Functional Invariants

- **INV-1 (Scoped Presentation Only)**: All theme-specific styles MUST be scoped under `[data-event-theme="pageant-editorial"]` or CSS custom properties. Global styles outside of event pages MUST NOT be modified.
- **INV-2 (Default Theme Parity)**: Events with `theme = "ELECTA_DEFAULT"` MUST render identically to the existing design system (Opal Slate-50 background, Slate-900 typography, Sky Blue accents, sharp zero-radius geometry).
- **INV-3 (Strict Type Safety)**: 100% TypeScript 5 strict mode compliance (no `any`, no non-null assertions `!`).
- **INV-4 (Tailwind v4 Conformance)**: Use `bg-linear-to-*` and canonical fraction utilities (`aspect-4/5`, `aspect-16/9`).
- **INV-5 (WCAG 2.1 AA Contrast)**: Minimum 4.5:1 contrast for body text, 3:1 for large text and interactive components.
